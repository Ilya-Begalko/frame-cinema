# FRAME — Cinema Club

Клиентское киноприложение. Каталог, постеры, актёры и трейлеры приходят из [TMDB](https://www.themoviedb.org/). Избранное, списки, оценки и заметки остаются в браузере. Отдельного сервера и аккаунта нет.

Интерфейс на английском. Комментарии в коде — на русском: они объясняют, что делает функция и какой приём React здесь используется.

## Запуск

```bash
npm install
cp .env.example .env
```

В `.env` впишите ключ TMDB:

```
TMDB_API_KEY=ваш_ключ
```

Локально ключ читает только процесс Vite (`npm run dev` и `npm run preview`). Переменная специально без префикса `VITE_`: такой префикс Vite вшивает в JavaScript, который скачивает браузер. Браузер ходит на `/tmdb/...`, а прокси в `vite.config.ts` добавляет ключ уже на стороне разработки.

На GitHub Pages прокси нет. Сборка берёт секрет репозитория `TMDB_API_KEY` и вшивает его в сайт, иначе каталог отвечает 404. Ключ тогда виден в скачанном JavaScript.

```bash
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Локальный сайт с горячей перезагрузкой |
| `npm run build` | Проверка TypeScript и сборка в `dist` |
| `npm run preview` | Просмотр собранного сайта, прокси TMDB тоже работает |
| `npm run lint` | Oxlint |
| `npm test` | Vitest: алгоритм настроений, коллекции, компоненты |
| `npm run test:e2e` | Playwright: поиск, избранное, перезагрузка |

## Где живут данные

**TMDB** — чужие данные: фильмы, жанры, люди, трейлеры, похожие картины. Их кэширует TanStack Query примерно на минуту.

**localStorage** — ваши данные, ключ `frame-cinema`. Сюда попадают избранное, «Посмотреть», «Просмотрено», оценки, заметки, свои подборки и язык каталога (`en-US` или `ru-RU`). Zustand с middleware `persist` сам читает и записывает этот ключ.

**React state** — то, что должно исчезнуть вместе с экраном: открытое меню, черновик поиска, вкладка в My Cinema, открытый трейлер. Фильтры Explore сюда не кладутся: они записаны в адресе, поэтому ссылку можно обновить и отправить.

localStorage не синхронизирует браузеры. Перенос — файл JSON на странице My Cinema или короткая ссылка `/share#...`. В hash после `#` лежит сама подборка. Hash браузер на сервер не отправляет. Если список длиннее примерно 4000 символов, ссылка не строится и остаётся экспорт файла.

## Экраны

**Discover** (`/`) объясняет идею: искать фильм по ощущению, а не по полке жанров. Здесь шесть настроений, редакционная программа из конкретных картин и пара «Tonight's double feature». Пара зависит от даты, поэтому вечером не прыгает при обновлении. «Surprise me» выбирает случайный фильм из восьми лучших непросмотренных.

**Explore** (`/explore`) — поиск по названию и режиссёру, фильтры года, жанра, страны, рейтинга, настроения и визуального стиля, сортировка по популярности, рейтингу и дате. На узком экране фильтры открываются панелью. Пустой запрос идёт в TMDB Discover. Текст ищет и фильмы, и человека: если имя похоже на режиссёра, ниже появляется его фильмография. Состояния: скелетоны, пустой результат, ошибка API с повторной попыткой.

**Film** (`/film/:id`) — кадр, постер, год, длительность, жанры, рейтинг, синопсис, режиссёр, актёры, похожие фильмы и трейлер в окне. Кнопки «Want to watch», «Favorite» и «Mark watched», личная оценка 1–10, заметка и добавление в свою подборку.

**My Cinema** (`/my-cinema`) — четыре полки: к просмотру, просмотренное, избранное, свои списки. Статистика считает только то, что уже лежит локально: число просмотренных, среднюю вашу оценку, частые жанры и режиссёров. Режиссёр появляется после того, как страница фильма успела его запомнить.

**Shared list** (`/share#...`) открывает чужую копию подборки и может сохранить её в этот браузер.

## Алгоритм настроения

TMDB не ищет «по чувству». Правило живёт в `src/features/mood-matching/moods.ts`.

У каждого настроения и визуального стиля есть:

- `genres` — идентификаторы жанров TMDB, основной вес (+5);
- `signals` — английские слова в описании и ключевых словах (+1.5);
- `avoid` — жанры, которые обычно спорят с ощущением (−3).

Без выбранного настроения порядок каталога не трогается, остаётся сортировка TMDB. С настроением клиент ещё раз ранжирует уже полученную страницу. В Discover жанры настроений уходят в TMDB через `|` («или»). Если человек явно выбрал жанр, он важнее настроения.

«Surprise me» выкидывает уже просмотренные id и берёт случайный фильм из восьми лучших. Случайность передаётся аргументом, поэтому тест не зависит от удачи.

## Структура

```
src/
├── app/            роутер и QueryClient
├── components/     кнопки, карточка, шапка — куски без знания страницы
├── features/       настроение, поиск, коллекции, страница фильма
├── pages/          экраны, которые собирают куски вместе
├── services/tmdb/  запросы к API
├── stores/         Zustand: личная коллекция
├── hooks/          свои хуки
└── lib/            мелкие чистые функции
```

Чистая функция не рисует экран и не ходит в сеть. `rank.ts`, `library.ts`, `stats.ts` и `transfer.ts` такие: их проверяет Vitest без браузера.

## Основы React на этом проекте

**Компонент** — функция, которая возвращает описание экрана. `MovieCard` получает фильм через `props` и сама ничего не запрашивает. Один и тот же компонент стоит и в каталоге, и в личной полке.

**JSX** выглядит как HTML внутри JavaScript. `className` — это `class`. Фигурные скобки вставляют значение: `{movie.title}`.

**Состояние** — данные, при изменении которых React заново вызывает компонент. `useState` на Discover хранит выбранные настроения, пока человек на этой странице. Родитель владеет данными, ребёнок только сообщает о клике. Так устроен `MoodSelector`: на главной выбор живёт в `useState`, на Explore — в адресе.

**Эффект** (`useEffect`) нужен для жизни вне экрана: прокрутка наверх при смене страницы, таймер поиска, запись заметки. Поиск ждёт 300 мс тишины и только потом меняет адрес, чтобы не спрашивать TMDB на каждую букву.

**Список** рисуют через `.map`. У каждого элемента есть `key` — стабильный `id` фильма, не номер в массиве. По ключу React понимает, какая карточка осталась, а какая новая.

**Роутер** связывает адрес и экран. `AppShell` — общая рамка. `Outlet` внутри него — место, куда подставляется текущая страница. `useParams` читает `:id` из `/film/843`. `useSearchParams` читает и пишет фильтры Explore.

**TanStack Query** загружает серверные данные. `useQuery` даёт `isLoading`, `isError`, `data` и `refetch`. Ключ запроса (`queryKey`) — имя кэша. Пока ключ тот же, повторный заход на страницу не бьёт сеть зря.

**Zustand** — общее состояние без прокидывания props через все этажи. `useCinemaStore((state) => state.favorites)` подписывает компонент только на избранное. Функции вроде `toggleFavorite` описаны отдельно от данных: в localStorage функции не сохранить.

**Гидрирование.** При первом кадре localStorage ещё может не прочитаться. `useStoreHydrated` прячет содержимое, пока чтение не закончится. Иначе кнопка «в избранное» успела бы записать фильм, а старый снимок тут же стёр бы его.

**Условный рендер** — обычный JavaScript: `movie ? <MovieCard /> : null` или ранний `return` с пустым состоянием.

## Тесты

Vitest проверяет правила без сети:

- Dreamlike поднимает фантастику выше комедии;
- избранное включается и выключается, просмотренное уходит из «Посмотреть»;
- импорт дополняет коллекцию;
- ссылка на подборку кодируется и читается обратно;
- кнопка настроения переключается;
- полка пишет в то же хранилище, что и страница фильма.

Playwright открывает настоящий Chromium, перехватывает `/tmdb`, ищет Inception, кладёт его в избранное, обновляет страницу и находит фильм в My Cinema.

## Стек

React, TypeScript, Vite, React Router, TanStack Query, Zustand, Tailwind CSS, Motion, Vitest, Testing Library, Playwright. Анимации смены страницы и карточек короткие, около 180–300 мс. При `prefers-reduced-motion` движение отключается.
